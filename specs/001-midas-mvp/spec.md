**Feature Branch**: `001-midas-mvp`

**Created**: 2026-05-19

**Status**: Draft

## Clarifications

### Session 2026-05-19

- Q: FinMind 使用免費方案還是付費方案？ → A: 免費方案
- Q: 首頁事件清單的排序規則為何？ → A: 固定事件類型優先級（財報 > 法說 > 重訊 > 一般公告），同類型依時間倒序
- Q: 財務指標方向標示的判定門檣為何？ → A: 統一門檣 ±5%（與前一季比較），> +5% 為改善↑，< −5% 為惡化↓，其餘為持平→

## User Scenarios & Testing *(mandatory)*

### User Story 1 — 盤後摘要看板 (Priority: P1)

身為長線投資人，我每天收盤後打開 Midas，首頁立即呈現今日追蹤股中有事件發生的清單（公告、財報、法說），以及大盤概況背景資訊，讓我在 2 分鐘內判斷今晚是否需要深入研究任何一檔。

**Why this priority**: 這是使用者每日使用的入口，沒有此頁面整個產品就失去主要使用情境。大盤概況提供研究背景，追蹤股事件清單回答「今晚要研究誰」這個核心問題。

**Independent Test**: 啟動應用後，首頁能顯示至少一筆虛構追蹤股事件（含公司名、事件類型、時間、AI 摘要一行）與大盤指數卡，即可驗收此故事的最小可行版本。

**Acceptance Scenarios**:

1. **Given** 使用者有追蹤股清單且今日有事件發生，**When** 開啟 Midas 首頁，**Then** 事件清單顯示公司名稱、事件類型（財報/重訊/法說/一般公告）、發生時間（HH:MM）、一行 AI 摘要（≤50 字），依事件類型的優先級排序，在同一優先級下以時間進行倒序排列。
2. **Given** 使用者有追蹤股清單但今日無任何事件，**When** 開啟首頁，**Then** 事件清單區顯示「今日無重要事件」提示文字，追蹤股以淡色清單呈現於下方。
3. **Given** 首頁已載入，**When** 使用者查看頁面，**Then** 資料更新時間戳（格式：YYYY-MM-DD HH:MM 更新）可見於頁面頂部或狀態列。
4. **Given** 今日有大盤資料，**When** 開啟首頁，**Then** 大盤概況卡顯示加權指數收盤點位、漲跌幅（含漲跌點）、成交量，以及與五日均量的比較。
5. **Given** 大盤概況卡已顯示，**When** 查看類股資訊，**Then** 顯示前五大漲幅與跌幅產業類股，以及三大法人買賣超彙整。

### User Story 2 — 個股事件詳情 (Priority: P2)

身為長線投資人，我點進一支追蹤股，能在同一頁面的事件分頁看到該公司今日完整事件清單、每個事件的 AI 摘要（100–200 字）、事件分類標籤，以及語意傾向標示，讓我在 3 分鐘內理解事件對公司的可能影響。

**Why this priority**: 盤後摘要看板觸發興趣後，個股事件詳情是使用者深入閱讀的第二層，是核心研究流程的必要環節。

**Independent Test**: 點選任一追蹤股進入詳情頁，能看到至少一筆事件含 AI 摘要（100–200 字）、來源連結、抓取時間戳、分類標籤，並顯示語意傾向標籤與免責聲明，即可驗收。

**Acceptance Scenarios**:

1. **Given** 使用者在首頁點選有事件的追蹤股，**When** 進入個股詳情頁，**Then** 預設顯示「事件」分頁，列出今日所有事件，每筆事件含：公告全文連結、AI 摘要（100–200 字）、分類標籤、抓取時間戳。
2. **Given** 事件摘要已顯示，**When** 查看 AI 摘要區塊，**Then** 摘要旁顯示資料來源名稱（如「公開資訊觀測站」）與資料抓取時間（ISO 8601 格式）。
3. **Given** 事件列表中有一筆事件，**When** 使用者點擊「查看原文」連結，**Then** 以系統預設瀏覽器開啟原始來源 URL，應用程式不嵌入 iframe。
4. **Given** AI 摘要已分析完成，**When** 顯示語意傾向，**Then** 顯示「偏正面」、「中性」或「偏負面」三種標籤之一，標籤旁附免責聲明文字：「此為 AI 摘要，僅供參考，不構成投資建議。」
5. **Given** 個股今日無任何事件，**When** 進入個股詳情事件分頁，**Then** 顯示「今日無公告或事件」提示，而非空白頁面。

### User Story 3 — 財務健康快覽 (Priority: P3)

身為長線投資人，我在個股詳情頁切換到「財務」分頁，能看到 EPS、毛利率、ROE、負債比、自由現金流五大指標的近三年季度趨勢，並附有改善/持平/惡化方向標示，讓我初步判斷公司財務是否健康，而不需要翻財報。

**Why this priority**: 財務健康是基本面投資的核心，但需要歷史資料抓取與數值計算，屬於獨立的資料管線，可在事件功能成形後再實作。

**Independent Test**: 個股詳情頁「財務」分頁能顯示至少一項指標的 3 年季度資料（含數值、趨勢方向標示、來源、更新時間），即可驗收。

**Acceptance Scenarios**:

1. **Given** 財務資料已從資料源抓取完成，**When** 開啟個股財務分頁，**Then** 顯示 EPS、毛利率（%）、ROE（%）、負債比（%）、自由現金流（百萬元）五項指標，各含近 12 季資料（折合約 3 年）。
2. **Given** 財務指標資料已計算完成，**When** 查看各指標，**Then** 每項指標旁顯示方向標示：「改善↑」「持平→」「惡化↓」，以最近一季相對前一季的變化為準。
3. **Given** 財務資料已顯示，**When** 查看資料說明區，**Then** 顯示資料來源名稱（如「FinMind」）及最後更新時間。
4. **Given** 某季財務資料尚未揭露（如最新季度財報未發布），**When** 顯示該季指標，**Then** 顯示「尚未揭露」文字，而非空值或 0。
5. **Given** 財務數值已計算，**When** 查看數值，**Then** 所有財務數值由後端 Python 計算後提供，頁面僅負責呈現，不在 UI 層進行任何數值計算。

### User Story 4 — 自訂追蹤清單 (Priority: P4)

身為長線投資人，我能新增、刪除追蹤股，並為每檔設定個人備忘文字，清單資料在應用關閉後持續保存，讓 Midas 持續追蹤我真正關心的公司。

**Why this priority**: 追蹤清單是其他所有功能的資料基礎，但管理功能（CRUD）可在初期以預設清單替代，故排在事件與財務功能之後。

**Independent Test**: 能新增一筆股票代號到清單並填寫備忘，重新啟動應用後資料仍存在，即可驗收。

**Acceptance Scenarios**:

1. **Given** 使用者在追蹤清單管理頁，**When** 輸入有效的台股代號（4–6 碼數字）並確認新增，**Then** 該股票出現在清單中，清單總數不超過 30 檔（FinMind 免費方案配額限制）。
2. **Given** 清單已達 30 檔，**When** 嘗試新增第 31 檔，**Then** 顯示「已達上限（30 檔）」提示，新增操作不生效。
3. **Given** 清單中已有一檔股票，**When** 使用者點選刪除並確認，**Then** 該股票從清單移除，對應的備忘也一併刪除。
4. **Given** 使用者開啟某檔股票的備忘編輯，**When** 輸入並儲存備忘文字，**Then** 備忘內容（最多 500 字）儲存至本機資料庫，重新啟動應用後可讀取。
5. **Given** 清單有多檔股票，**When** 使用者在搜尋框輸入公司名稱或股票代號，**Then** 清單即時篩選並顯示符合的項目，清空搜尋後恢復完整清單。

### User Story 5 — 盤後自動更新 (Priority: P5)

身為長線投資人，我希望 Midas 在每天收盤後自動抓取當日資料，讓我打開就能看到最新分析，不需要手動觸發。

**Why this priority**: 自動更新是便利性功能，提升使用黏著度，但不影響核心功能的正確性。初期可以手動更新替代，故排在後期。

**Independent Test**: 啟動應用時若當日資料尚未抓取，能自動開始背景更新，狀態列顯示進度，完成後資料可讀取，整個過程中主介面仍可操作，即可驗收。

**Acceptance Scenarios**:

1. **Given** 使用者在收盤後（15:00 後）開啟 Midas，且當日資料尚未抓取，**When** 應用啟動，**Then** 自動觸發背景更新，主介面維持可操作狀態（舊資料仍可瀏覽）。
2. **Given** 背景更新進行中，**When** 使用者查看底部狀態列，**Then** 狀態列顯示更新進度（如「正在更新… 2/5」或百分比）與目前更新項目名稱。
3. **Given** 背景更新完成，**When** 更新成功，**Then** 首頁資料自動刷新，狀態列更新時間戳更新為當前時間。
4. **Given** 背景更新因網路錯誤或 API 限流失敗，**When** 更新失敗，**Then** 狀態列顯示錯誤提示（含失敗原因），並顯示「重試」按鈕，原有快取資料仍保持可讀。
5. **Given** 應用在收盤前開啟（15:00 前），**When** 使用者查看資料，**Then** 應用不自動觸發更新，顯示前一交易日資料並標注資料日期。

---

### Edge Cases

- 使用者追蹤股清單為空時，首頁事件區顯示「尚未新增追蹤股」引導提示。
- 非交易日（週末、國定假日）開啟應用時，顯示最後交易日資料並明確標注日期。
- 個股 AI 摘要生成失敗（LLM API 逾時或限流）時，顯示「AI 摘要暫不可用，請查看原文連結」，不顯示空白區塊。
- 財務資料來源（FinMind）回傳錯誤時，個股財務分頁顯示「資料暫時無法取得，上次更新：[timestamp]」，而非崩潰。
- 同一事件有多個來源抓取時，去重後顯示，保留最早的抓取時間戳與最完整的 URL。
- 使用者在更新進行中關閉應用，下次開啟時從頭重新觸發更新（不支援斷點續傳）。
- 追蹤股代號輸入驗證：只允許 4–6 碼純數字，不允許英文股號（非台股）。

## Requirements *(mandatory)*

### Functional Requirements

#### 首頁 / 盤後摘要看板
- **FR-001**: 首頁 MUST 顯示大盤概況卡，含加權指數收盤點位、漲跌幅、成交量與五日均量比較。
- **FR-002**: 首頁 MUST 顯示前五大漲幅與跌幅產業類股（含漲跌幅百分比）。
- **FR-003**: 首頁 MUST 顯示三大法人（外資、投信、自營商）買賣超彙整數字（億元）。
- **FR-004**: 首頁 MUST 顯示追蹤股事件清單，今日有事件者顯示於上方，無事件者以淡色顯示於下方。
- **FR-005**: 每筆事件 MUST 顯示公司名稱、股票代號、事件類型、發生時間、一行 AI 摘要（≤50 字）。
- **FR-027**: 事件清單 MUST 依以下固定優先級排序：財報（1）> 法說會（2）> 重大訊息（3）> 一般公告（4）；同優先級內依事件發生時間倒序排列。
- **FR-006**: 資料更新時間戳 MUST 以「YYYY-MM-DD HH:MM 更新」格式顯示於頁面可見位置。

#### 個股詳情頁
- **FR-007**: 個股詳情頁 MUST 包含「事件」與「財務」兩個分頁（Tab）。
- **FR-008**: 事件分頁 MUST 列出當日所有事件，每筆含公告全文連結、AI 摘要（100–200 字）、分類標籤、資料來源、抓取時間戳。
- **FR-009**: AI 摘要 MUST 附語意傾向標籤（偏正面 / 中性 / 偏負面）與固定免責聲明文字。
- **FR-010**: 「查看原文」連結 MUST 以系統瀏覽器開啟外部 URL，不在應用內嵌入網頁。
- **FR-011**: 財務分頁 MUST 顯示 EPS、毛利率、ROE、負債比、自由現金流五項指標的近 12 季資料。
- **FR-012**: 每項財務指標 MUST 附方向標示與資料來源及更新時間；方向判定規則為：最近一季相對前一季變化率 > +5% 為改善↑，< −5% 為惡化↓，其餘為持平→；此規則適用於全部五大指標。
- **FR-013**: 財務數值 MUST 由後端 Python 計算後傳遞給 UI 呈現，UI 層不執行任何數值計算。
- **FR-014**: 尚未揭露的財務資料 MUST 顯示「尚未揭露」字樣，不可顯示空值或 0。

#### 追蹤清單管理
- **FR-015**: 系統 MUST 支援新增 / 刪除追蹤股，上限 30 檔（受 FinMind 免費方案每日請求上限約束）。
- **FR-016**: 系統 MUST 支援每檔股票的個人備忘（最多 500 字）的新增、編輯、刪除。
- **FR-017**: 清單 MUST 支援以公司名稱或股票代號即時篩選。
- **FR-018**: 所有追蹤清單資料與備忘 MUST 持久化於本機 SQLite 資料庫。

#### 資料快取與節流（FinMind 免費方案）
- **FR-028**: 系統 MUST 實作本機快取，每檔股票的財務資料快取有效期 MUST 為 7 天，當日事件資料快取有效期 MUST 為當日收盤後至隔日開盤前。
- **FR-029**: 每次盤後批次更新 MUST 控制對 FinMind 的總請求數在 800 次以內（免費方案每日上限的安全緩衝）。
- **FR-030**: 若 FinMind API 回傳限流錯誤（HTTP 429），系統 MUST 暫停請求至少 60 秒後再重試，最多重試 3 次。
- **FR-031**: 每日更新前 MUST 優先使用有效快取，僅對快取過期的股票發出 API 請求。
- **FR-032**: Gemini LLM API 每日呼叫次數 MUST 不超過 50 次（免費方案配額）；超出配額時，AI 摘要生成 MUST 跳過並於 UI 顯示「今日 AI 摘要配額已用盡」，不可崩潰或拋出未處理例外。

#### 自動更新機制
- **FR-019**: 應用啟動時 MUST 自動偵測當日資料狀態；若為收盤後（≥15:00）且當日資料尚未抓取，立即以應用內背景執行緒觸發更新；應用關閉時背景更新 MUST 隨之終止，不在背景常駐。
- **FR-020**: 背景更新 MUST NOT 阻塞主介面操作，舊快取資料在更新期間仍可瀏覽。
- **FR-021**: 底部狀態列 MUST 顯示更新進度（項目/總數或百分比）與最後更新時間戳。
- **FR-022**: 更新失敗時 MUST 於狀態列顯示錯誤提示並提供「重試」按鈕。
- **FR-023**: 更新成功後 MUST 自動刷新首頁顯示資料，無需使用者手動重新整理。

#### 介面結構
- **FR-024**: 應用 MUST 採左側導航列、右側主內容區、底部狀態列的三欄式結構。
- **FR-025**: 應用 MUST 預設深色模式，並提供深色 / 亮色模式切換選項。
- **FR-026**: 使用者 MUST 能從首頁事件清單點選進入對應個股詳情頁。

### Key Entities

- **TrackedStock（追蹤股）**: 使用者自訂的股票清單項目，含股票代號、公司名稱、加入時間、個人備忘（≤500 字）。
- **MarketEvent（市場事件）**: 個股的公告/財報/法說等事件，含公司代號、事件類型（`financial_report` / `investor_conference` / `material_news` / `general_announcement`）、事件類型優先級（整數 1–4）、發生時間、原文 URL、AI 摘要（100–200 字）、語意傾向、來源名稱、`fetched_at` 時間戳。
- **FinancialMetric（財務指標）**: 個股季度財務數值，含公司代號、指標類型（EPS/毛利率/ROE/負債比/FCF）、期別（YYYY-QN）、數值、方向標示（`improving` / `stable` / `declining`）、與前一季變化率（%）、來源、`fetched_at`。方向判定規則：|change_pct| > 5% 決定改善或惡化方向。
- **MarketOverview（大盤概況）**: 每日大盤快照，含指數點位、漲跌幅、成交量、五日均量、類股漲跌排行、三大法人買賣超、`fetched_at`。
- **UpdateJob（更新任務）**: 背景更新執行紀錄，含觸發時間、完成時間、狀態（進行中/成功/失敗）、失敗原因。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者從開啟應用到看到今日完整盤後事件清單，所需時間少於 15 秒（快取情況下）。
- **SC-002**: 使用者能在 15 分鐘內完成所有追蹤股的盤後事件掃描。
- **SC-003**: 使用者能在 3 分鐘內理解任一個股當日事件的影響方向（含摘要閱讀）。
- **SC-004**: 首頁頁面切換響應時間在 200 ms 以內（不含資料更新）。
- **SC-005**: 背景更新進行期間，主介面操作（頁面切換、清單捲動）不出現卡頓。
- **SC-006**: 資料更新失敗時，使用者能在 10 秒內看到錯誤提示並使用手動重試功能。
- **SC-007**: 追蹤清單新增、刪除、備忘儲存操作在應用重啟後 100% 保留。
- **SC-008**: 所有 AI 摘要旁均有免責聲明與來源標示，使用者不需尋找即可看見。

## Assumptions

- 資料來源以 FinMind API（台股財務資料）及公開資訊觀測站（MOPS，重大訊息）為主，無需使用者輸入帳密。
- FinMind 使用**免費方案**，每日 API 請求上限約 1,000–3,000 次；架構設計需以 7 天長快取、批次節流、30 檔追蹤上限為前提，避免超出免費配額。
- 使用者在盤後（15:00 之後）使用應用，且具備穩定的網路連線以觸發資料抓取。
- MVP 僅支援 Windows 10/11 桌面平台，不包含 macOS 或行動裝置。
- 使用者不需要登入帳號，所有資料儲存於本機 `%APPDATA%\Midas` 路徑下的 SQLite 資料庫。
- LLM API（用於生成摘要與語意標籤）由應用內建設定管理，MVP 不提供使用者自訂 LLM 供應商的 UI。
- 財務數值計算由後端 Python 服務負責，前端 UI 層僅負責資料呈現。
- 三大法人、類股漲跌等大盤資料以當日收盤後一次性批次抓取為主，不做盤中即時更新。
- 同一份股票資料若有多筆相同事件（來源不同），以去重後最早 `fetched_at` 為準。

## Non-Goals (Out of Scope)

以下功能明確不在 MVP 範圍內，計畫於 Phase 2 / Phase 3 實作：

| 功能 | 預計階段 | 說明 |
|------|---------|------|
| 評價分析（本益比、股價淨值比等評估） | Phase 2 | 需要更複雜的估值模型 |
| 法說會摘要專屬頁面 | Phase 2 | MVP 以事件清單呈現，Phase 2 再獨立模組化 |
| 研究筆記（Markdown 編輯器） | Phase 2 | MVP 僅有純文字備忘 |
| 智慧提醒（推播通知、Email 通知） | Phase 2 | 需要通知基礎設施 |
| 產業地圖視覺化 | Phase 3 | 需要額外圖表元件與產業分類資料 |
| 社群輿情分析（PTT / 股市看板） | Phase 3 | 需要額外爬蟲與情感分析管線 |
| 回測引擎 / 策略模擬 | Phase 3 | 超出基本面投研範疇 |
| 選股篩選工具 | Phase 3 | 超出 MVP 追蹤清單範疇 |
| 雲端同步 / 帳號系統 | Phase 3 | 在地優先原則，MVP 不需雲端 |

## Future Considerations

以下為 Phase 2 / Phase 3 功能的擴充點（Extension Points），MVP 架構設計時應留意不封閉這些入口：

- **評價分析模組**（Phase 2）: FinancialMetric 實體設計需保留彈性以支援估值指標欄位擴充。
- **法說摘要模組**（Phase 2）: MarketEvent 的事件類型標籤需預留「法說會」類型；LLM 摘要管線需可插入更長的逐字稿輸入。
- **研究筆記**（Phase 2）: TrackedStock 備忘欄位未來應升級為獨立 Note 實體，支援 Markdown 與標記。
- **智慧提醒**（Phase 2）: UpdateJob 執行後需能觸發「有重要事件」的訊號，作為後續通知系統的輸入。
- **排程常駐更新**（Phase 2）: 目前採啟動時觸發；Phase 2 可升級為 Windows Task Scheduler 整合或 system tray 常駐 process，UpdateJob 資料結構設計時應不封閉此路徑。
- **產業地圖**（Phase 3）: MarketOverview 的類股資料需保留原始類股代碼，以支援未來的圖形化展示。
- **社群輿情**（Phase 3）: MarketEvent 需預留 `sentiment_source` 欄位，以支援多來源情感分析整合。
